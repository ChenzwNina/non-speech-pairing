# freeform — no options, model speaks as B

The MCQ eval one folder up (`../eval_realtime.py`) hands the model both gold answers and
asks it to pick. That is a generous test: the options themselves reveal what kind of
contrast is in play, and a model can work backward from them.

Here the model gets **no options**. It hears one dialogue — Speaker A's line, then B's
non-speech reaction — and has to produce B's next line itself, in role, out loud.

```
audio in:   A: "I finished the full twenty-six-mile trail loop this morning."
            B: [grunt]
model out:  (as B, spoken) "..."
```

## Design

**One audio per trial.** Both versions of every pair are run independently — 15 pairs × 2
vocalizations = 30 trials. The two versions share an identical turn 1 and differ only in
B's sound, which is what makes the comparison meaningful: if a model's two replies come
out doing the same conversational work, the sound contributed nothing.

**Nothing is leaked.** The model is never told which sound played, never told the six
categories exist, and never shown either gold answer. It is told only that B reacted "with
a non-speech sound, using no words," and asked to say B's next line.

**A fresh session per trial**, so nothing carries over between items.

**Audio out by default.** The model speaks the reply (`--modality audio`, saved to
`out/audio_reply/`), because "say what B would say next" is a speech act and the prosody is
part of the answer. The transcript is what gets scored. `--modality text` skips the voice.

**Optional control condition** (`--control`): turn 1 alone, no vocalization, once per pair.
This is the floor — whatever a model says from the words alone is not evidence it
understood any sound.

## Scoring

Free-form output needs a judge, and a single number would hide the interesting failure.
`judge.py` runs two independent passes.

### 1. Alignment (per trial)

The judge sees turn 1, the model's reply, and the pair's **two gold interpretations in
randomized order** — without being told which sound played, so it cannot inherit the
answer. It picks which interpretation the reply is pragmatically consistent with, or
`NEITHER`.

- `aligned` — chose the interpretation belonging to the sound that actually played
- `swapped` — chose the other version's interpretation
- `neither` — the reply is generic enough to follow either reading

The judge is told to match on **conversational function** (teasing, reproaching,
celebrating, objecting, reluctantly agreeing…), not on shared topic words — both
interpretations describe the same situation, so vocabulary overlap is uninformative. It is
also told to be strict about `NEITHER`: a bland acknowledgement or a neutral question is
not a weak match, it is no match.

Two extra flags per trial: `names_the_sound` (the reply describes or asks about the sound —
"why are you sighing" — instead of just continuing, which the prompt forbids) and
`plausible_next_line` (is this a real conversational turn at all).

### 2. Differentiation (per pair)

Alignment alone is gameable. A model that produces one fixed reply for both versions scores
~50% alignment while understanding nothing. So the judge separately sees turn 1 and **both**
replies for a pair, in randomized order, and decides whether they perform clearly different
conversational functions — with explicit instruction that different wording, politeness, or
intensity for the same move does **not** count.

The headline number to read is **pairs where both replies aligned**, cross-checked against
**pairs whose two replies did different work**. Alignment high but differentiation low means
the model is riding one reply that happens to fit half the dataset.

## Running

```bash
python3 predicting_response_upgraded/freeform/run.py --control
```

```bash
python3 predicting_response_upgraded/freeform/judge.py
```

Smoke-test a couple of trials first:

```bash
python3 predicting_response_upgraded/freeform/run.py --limit 2
```

`--resume` on `run.py` keeps replies already collected. Inputs come from
`../out/audio_manifest.json`, so the audio must have been generated by
`../generate_audio.py` first.

## Output

- `out/responses.json` — one row per trial: turn 1, the actual vocalization, both golds,
  the model's reply text, and the path to its spoken reply
- `out/audio_reply/*.mp3` — the model speaking as B
- `out/scored.json` — alignment verdicts per trial, differentiation per pair, and the
  summary block

## A note on what this measures

A model can pass the MCQ by eliminating the option that reads oddly. It cannot pass this by
elimination — it has to have actually heard the reaction and let it steer what B says. In
the first two-trial smoke test, `gpt-realtime-2.1` answered a gasp with "That's incredible —
were you out there before sunrise?" and a grunt, after the same turn 1, with "That's
seriously impressive. Are you feeling okay?" Both are warm and admiring; the grunt's gold
reading is skeptical and asks for proof. Same conversational move twice, so the sound made
no difference — a miss the MCQ format would have scored as a coin flip.
